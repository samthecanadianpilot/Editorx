What landed.

Palette & theme

  • Jet black with cohesive cool tint v5 --bg-1: #0A0B0D (OKLCH 8% L · 0.005 C · 240 H). Reads pure black to the eye but every neutral leans the same hue — satisfies PRODUCT.md anti-reference against "pure #000/#fff without cohesive strategy."
  • Surface tiers --bg-2 #111114 · --surface-1 #16171A · --surface-2 #1E1F23 · --surface-3 #2A2B30. Every step roughly 4% lightness. Predictable elevation scale, no random shadows.
  • Tinted neutrals replace pure #FFFFFF / #000000 v4 Active pills, primary CTAs, focus rings now use #F1F2F3 off-white and #1B1D1F off-black ink — same cool-tint hue as the surfaces.
  • Quiet active states — UI recedes v4 Active workspace tabs, sidebar tabs, tool buttons, play button, selected cards dropped from 100% lightness to 92%. Still high contrast (~14:1 AAA) but no longer the brightest pixel on screen. Per PRODUCT.md design principle #1: "Focus on the canvas — UI should recede."

Apple glass on floating chrome v5

  • Topbar & toolbar rgba(10,11,13,0.62) + blur(28px) saturate(170%) + inset 0 1px 0 rgba(241,242,243,0.04) (macOS lit-from-above edge highlight).
  • Sidebars (left Browser, right Inspector) Floating glass panels: rgba(15,16,19,0.74) + blur(28px) saturate(170%).
  • Modals Heavy frost: rgba(20,21,24,0.72) + blur(40px) saturate(180%) + 14px radius. The macOS Big Sur "frosted material" look.
  • Command palette · context menus · onboarding tour · meta pills · timecode All floating popovers get glass with 14-40px blur. Tool-group pills and workspace-tab outer pill use 20px blur + 150% saturation.
  • Discipline: glass only on floating chrome Viewer canvas, timeline tracks, clip backgrounds, dashboard cards stay flat. Per impeccable: "rare and purposeful, or nothing." Glass on background surfaces would compete with the canvas content.

Typography

  • Apple-native sans stack v2 -apple-system, BlinkMacSystemFont, "SF Pro Text/Display", "Inter", "Helvetica Neue". SF Pro on Apple devices, Inter (Google Font) on everything else.
  • Marketing-hero scale per apple.com/final-cut-pro Starter headline clamp(44px, 6vw, 88px) · weight 700 · tracking -0.045em. Dashboard clamp(40px, 4.4vw, 64px). Starter title (sign-in) clamp(40px, 4vw, 56px).
  • "Intelligence" gradient text-fill on hero emphasis Marketing surfaces only. The em word in "Cut, mask, and color in the browser" + "Your projects." renders in linear-gradient(135deg, #FFB070 0%, #FF6F91 50%, #B65CFF 100%) — Apple's signature warm-orange→pink→purple from the FCP "Intelligence" section.
  • Timecode + monospace UI uses SF Mono "SF Mono", "Menlo", "JetBrains Mono". Tabular nums on every numeric column (timecode, durations, axis ticks) to prevent column jitter.
  • Editorial serif retained as opt-in only Fraunces preserved as --font-serif via .ff-serif utility class. Not the default.

Apple component patterns v3

Direct ports from the iPhone 17 Pro screenshots you shared.

  • Segmented pill: workspace tabs (Edit / Color / Effects / Export) The "200mm / 100mm / 48mm" pattern. Dark outer pill, active segment becomes a tinted off-white pill with black text. Phosphor icons swap to filled weight when active.
  • Segmented pill: sidebar tabs (Library / Trans / Color / FX / Titles / Graphics / Masks) Same pattern, stacked icon-above-label. The "Center Stage / Dual Capture" reference. Active = white pill, filled black icon + label.
  • "+ pill" CTA pattern The "Compare iPhone cameras +" form. Dark rounded pill, label left, filled circular plus icon on the right end. Applied to + Add in Library, Import media button, dashboard + New Project.
  • Icon-card grid (FX / Transitions / LUTs / Titles / Masks) Active card = solid off-white with black contents. Hover = subtle surface lift.
  • Outline default → filled active icon weight Phosphor regular + fill weights both loaded. CSS targets i.icon-ph::before and swaps font-family: 'Phosphor-Fill' on .active / .selected parents. iOS tab-bar behavior — outline by default, filled when active.
  • Top-bar outline pills (New / Open / Save) apple.com nav "Explore" pattern. 32px height, 999px radius, 1px hairline border.

The one blue moment

  • .export-btn is the sole chromatic anchor #0071e3 Same role as the blue "Buy" button in apple.com/iphone-17-pro top nav: the most important single action gets the brand-blue treatment. Every other surface in the editor is monochrome — the eye locates the destination CTA instantly.
  • Three rounds of blue removal sweep All #0a84ff, rgba(10,132,255, *), rgba(0,132,255, *) references swept to monochrome or var(--accent). Only the EXPORT button retains blue.

Icons

  • Phosphor Icons (regular + fill weights) Replaced Lucide app-wide via a drop-in shim (webapp/icons.js). Every existing <i data-lucide="X"> keeps working untouched; the shim maps the Lucide name to the Phosphor equivalent and renders <i class="ph ph-NAME"> at runtime. ~70 icons mapped.
  • SF Symbols not legally available on the web Apple's license forbids SF Symbols use outside Apple platforms. Phosphor is the closest free, legal SF-Symbols-like set (rounded glyphs, same vocabulary, multiple weights).

Motion

  • Exponential ease-out everywhere v4 --t-fast ease-out-quart · --t-base ease-out-quint · --t-slow, --t-apple ease-out-expo. All cubic-bezier(0.16, 1, 0.3, 1) family.
  • Bounce / overshoot killed Previous --t-spring: cubic-bezier(0.34, 1.56, 0.64, 1) overshoot was banned by the impeccable skill (shared design law: "No bounce, no elastic"). Replaced with exponential ease-out.
  • Reduced-motion respected @media (prefers-reduced-motion: reduce) disables all transitions globally.

Accessibility

  • WCAG 2.4.7 focus indicators 22 :focus-visible selectors added across every interactive surface. 2px outline + 2px offset on keyboard focus only — pointer focus stays clean. Previously zero focus-visible rules existed.
  • aria-labels on icon-only buttons Count went 2 → 17. Transport buttons (Play/Stop/Skip/Rewind/Forward/Home/End/Undo/Redo), tool buttons (Select/Blade/Text/Hand/Snap), modal close X's all now have accessible names. aria-hidden="true" on decorative icons.
  • Tabular numerics font-variant-numeric: tabular-nums on timecode, durations, axis ticks. No column jitter as digits change.

Bugs fixed

  • var(--select) undefined → invisible clip selection border Selected clip border was falling back to browser default. Now uses var(--accent).
  • Dashboard card aspect-ratio glitch Inline style="aspect-ratio:${canvasW}/${canvasH}" made 9:16 portrait projects have ~600px-tall thumbnails while 16:9 cards were ~180px. Locked thumbs to 16:9, letterbox portrait content, added aspect-ratio badge ("1:1" / "16:9" / "9:16") in top-left.
  • White-text-on-cream-accent invisible buttons When accent shifted from blue to cream, six places had hardcoded color:#fff on background:var(--accent) — rendering white-on-white. Swept to var(--accent-ink): cmdk active row, onboarding Next button, list-card selected icon, context-menu hover, btn-pulse keyframe, panel-resizer hover, focus ring glow.
  • Dead --accent-glow token removed Declared but never used. Pure dead code.
  • Film-grain overlay removed HTML element + CSS block + override all stripped. Contradicted the "no shiny things" brief.

Empty states

  • Library: teach the interface "No media yet · Import video, audio, or images" → "Start with media" + "Drop video, audio, or images here, or pick from your computer. Clips appear in this list and drag onto the timeline below." + ⌘O shortcut hint + supported formats list. Per impeccable product reference: "Empty states that teach the interface, not 'nothing here.'"

What's left.

Most of these need either new JS, HTML restructure, or your decision — not just CSS.

Editor features (need JS)

  • Skimmer line Orange line that follows the mouse over timeline tracks for instant frame preview, like FCP. CSS already in place (#skimmer / .skimmer styled, --skimmer #ff9f0a). Needs a mousemove handler on #timeline-tracks in ui.js that positions the line at e.clientX relative to the tracks. ~15 lines of JS.
  • Viewer crosshair + safe-zone + grid overlays Checkboxes ("Safe zones", "Crosshair", "Grid") already render under the viewer. Each currently does nothing on toggle. Need canvas-side draw logic: outer 5% / inner 15% safe rectangles, center crosshair, third-thirds rule grid. Hook into the same renderViewer cycle that already paints frames.
  • In/out point markers on clip edges Per the FCP spec. Render small triangle markers at clip.in and clip.out positions inside each clip block. ~30 lines in renderClips.
  • Magnetic timeline behavior on drag Currently clips snap to a fixed grid. FCP-style magnetic timeline = clips collide with each other and push neighbors. Significant — needs engine.js changes to model the timeline as a graph and recompute positions on drop.

Inspector (needs HTML restructure)

  • Collapsible Inspector sections Per your FCP spec: Video, Transform (X/Y · scale · rotation), Crop, Distort, Stabilization, Color, Audio, Clip Info — each as a collapsible section with animated chevron. Current inspector is a flat property list. Needs HTML markup added per section + a small accordion handler.
  • Color wheels (Lift / Gamma / Gain) Three circular gradient color pickers per the brief. Doable in canvas/SVG (you said Swift was optional — I rejected it for the web deploy). ~1-2 hours of focused work.

Marketing surface refinement

  • Starter screen + dashboard not yet jet-blackified Phases v4 (impeccable) and v5 (jet-black + glass) are scoped to #app only. The starter screen and dashboard still run on the earlier warm-cream Apple-marketing tokens (which look great in isolation but now diverge from the editor). Decision needed: should marketing surfaces also adopt jet-black-glass, or stay warm as a deliberate contrast moment?
  • Dashboard project cards — glass treatment? Currently flat with subtle hover. Could pick up the floating-glass treatment if marketing surfaces move to jet-black.

  • Skeleton loading states Long-running operations (Whisper transcription, beat detection, render queue) currently show spinners. Should be skeleton screens per the brief.

Anti-references explicitly avoided.

From PRODUCT.md + the impeccable shared design laws.

  • Pure #000 / pure #fff dark mode Replaced with cool-tinted OKLCH neutrals (hue 240, chroma 0.005). Every neutral cohesive.
  • Side-stripe borders Never used. Full borders, hairline separators, or nothing.
  • Bounce / elastic motion Eliminated. All transitions exponential ease-out.
  • Decorative glassmorphism Glass is on floating chrome only (topbar, sidebars, modals, popovers). Never on background surfaces, never on cards. Apple's actual pattern.
  • Generic SaaS card grids Preset cards differentiate by content (LUT swatches, transition motion previews, FX category icons). Not identical rectangles.
  • "Nothing here" empty states Replaced with teaching copy + shortcut hints + supported formats.
  • Hero-metric SaaS template Not applicable to the editor surface. Marketing surfaces use cinematic typography, not big-number-small-label.
